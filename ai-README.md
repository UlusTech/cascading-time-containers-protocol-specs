# `ai-*` — CTCP design snapshot

Worked examples of the container/cascade model as discussed. Written in the
tree style of `example.xml`, with the design decisions marked on the nodes.

Not a schema. Not normative. A drawing of the idea.

## Files

| file | shows |
|---|---|
| `ai-example.xml` | the calendar view. Dinner party in two spaces at once. |
| `ai-inheritance.xml` | "süt almıştım" — one container, ten parents, which one wins. |
| `ai-capacity.xml` | exclusion as containment. Auto-placement. Recurrence. |
| `ai-scales.xml` | ns logs and 14th-century wars in one protocol. Bridging. |

Each file is self-contained: a `<projection>` (what an engine draws) followed
by the `<store>` rows that produced it.

See [ai-diagrams.md](./ai-diagrams.md).

## Notation

```
kind= key=    generated by a plugin. NOT in the database.
id=           a stored row.
point=        one stored interval, drawn as two tree nodes.
              A tree cannot hold an interval, only points.
<!-- ... -->  the unmaterialised fractal. Never stored, generated on demand.
```

Paths use your own notation, `kind/key/kind/key/…`, which is sugar for
`[{kind, key}, …]`. `key` is an opaque string — the engine never reads it.

```
gregorian-year/2026/gregorian-month/12/gregorian-day/31/utc-hour/16/utc-minute/30
gregorian-year/*/gregorian-month/*/gregorian-day/*/utc-hour/02/utc-minute/00
gregorian-year/{year % 2 == 0}/gregorian-month/08/gregorian-day/26
slot/1
mono-ns/9182773310041
```

## The rules these files encode

**Everything is a container.** One entity. A cascade is the interior of a
container — it has no id of its own, so `SpaceID = ContainerID`.

**A placement is per space.** One container, one row, many positions. Entry
Talk is slot 1 in `dinner-party` and 16:30–16:40 in `time`, simultaneously.

**Depth is precision.** Every path is an interval; where it stops decides
how wide. `start`/`end` add an explicit span on top. Both mechanisms exist.

**Absence means inherit.** No placement in space S → walk up every chain that
reaches S, intersect what lands, ignore what doesn't. There is no
`tag: "inherited"` — two encodings of one fact is a bug generator.

**`*` means all, not unknown.** Opposite quantifier to `Partial<T>`. This is
why CTCP never implements RFC 5545: recurrence is a wildcard inside a
coordinate, not a rule language bolted alongside.

**Exclusion is containment.** No conflict edges, no resource declarations.
Two occupants of one container's cascade wanting overlapping time is the
conflict. Toilet blocks coding but not phone because they are contents of
different containers.

**Store the expensive edge, derive the cheap one.** `<children>` is stored
because deriving it means a table scan. Parents are derived, never stored —
they are already in the child's placements.

**Root vs draft is derived, never declared.** Root = 0 placements and ≥1
container placed in it. Draft = 0 placements and nothing placed in it. An
`isRoot="true"` goes stale the moment someone places it.

**The engine needs exactly two functions from a plugin.**

```
compare(space, pathA, pathB) -> -1 | 0 | 1
normalize(space, path)       -> path      // carry: 0:70 -> 1:10
```

Everything else — leap years, labels, locale, "her 2 yılda bir" — stays
behind the wall. Both sync, so WASM works. Gregorian is a plugin, not the
core. There is no field named `time`, `timestamp`, `clock`, or
`defaultSpace` anywhere.

**Resolution is three-valued.**

```
{ tag: "in",        intervals: Interval[], via: ContainerID[] }
{ tag: "unbounded" }
{ tag: "conflict",  chains: [...] }
```

`conflict` is normal traffic, not an exception — for org logs it is the
misplaced-entry detector. Never silently pick a winner.

## Still open

1. **Carry off the top.** `normalize()` overflows the highest segment — does
   the space grow a level upward, cap, or error?
2. **Range extents.** "40 veya 45te biter" — an interval-valued *end*,
   distinct from coarse depth. Not encodable in these files.
3. **`<floating>` grammar.** Engine-interpreted or plugin-interpreted? If
   engine, it is protocol surface and needs pinning down. If plugin, the
   engine cannot auto-place without loading one.
4. **Cycles.** A places in B, B places in A. No type forbids it; the resolver
   must return a tagged failure.
5. **Two cascades per container?** `whos-talk.md:125` says one interior or
   none. The loose children beside a grid in `example.xml` hinted otherwise.
   These files assume **one**.
